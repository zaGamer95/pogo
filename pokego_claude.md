# pokego_claude.md — site reference

Quick reference for the structure of this site. Keep it current: **update this file in the same change whenever you add or alter a page, data file, schema, or storage key.**
Game concepts (CP, IVs, leagues, Max Battles, trading…) live in [`docs/pogo-concepts.md`](docs/pogo-concepts.md).

---

## 1. Stack at a glance

- Vite + React 19 + TypeScript, `HashRouter` (works on GitHub Pages without server rewrites), plain CSS (`src/styles.css`, dark/light via `prefers-color-scheme`).
- **No backend.** Game data = static JSON in `public/data/` built by `scripts/fetch-data.mjs`. User data = browser `localStorage`.
- `public/data/` is **gitignored**. It's regenerated by `npm run data` (and automatically by `npm run dev` if missing, and by CI).
- Deploy: `.github/workflows/deploy.yml` → on push to `main` + every 6 h: `npm ci → npm run data → npm run build → GitHub Pages`.

## 4. Data files (`public/data/`, built by `scripts/fetch-data.mjs`)

| File | Source | Shape |
| --- | --- | --- |
| `pokemon.json` | PvPoke gamemaster (+ PokeMiners Dynamax flags) | `Species[]` |
| `moves.json` | PvPoke moves + PokeMiners PvE stats | `Record<MOVE_ID, Move>` |
| `types.json` | PokeMiners `typeEffective` | `{ types: string[18], chart: {atk: {def: mult}} }` |
| `cpm.json` | PokeMiners `PLAYER_LEVEL_SETTINGS` | `number[]`, index = `(level-1)*2`, levels 1–55 in 0.5 steps (half levels interpolated) |
| `events.json` | ScrapedDuck `events.min.json` (LeekDuck) | `LeekEvent[]` (raw) |
| `raids.json` | ScrapedDuck `raids.min.json` | `LeekRaid[]` (raw) |
| `shinies.json` | LeekDuck `shiny/pms.json` | `{ dex, form: string\|null, released: 'YYYY-MM-DD'\|null }[]` |
| `names.json` | LeekDuck `shiny/name.json` | `Record<dex, { en, ko }>` |
| `news.json` | Official RSS `pokemongolive.com/feed` | `{ title, link, date }[]` |
| `pvp/formats.json` | PvPoke formats + cups that have rankings | `PvpFormat[]` (`key = "<cup>-<cp>"`) |
| `pvp/<cup>-<cp>.json` | PvPoke rankings | `{ overall?, leads?, closers?, switches?, attackers?, chargers?: RankEntry[] }` (overall top 200, others top 60) |
| `meta.json` | pipeline | `{ updated, pvpokeUpdated, counts }` |

### Key types (see `src/lib/data.ts`)

```ts
Species  { id /* pvpoke speciesId, e.g. "machamp", "machamp_shadow", "charizard_mega_y", "marowak_alolan" */,
           name, dex, types[], atk, def, hp /* base stats */, fast[], charged[] /* MOVE_IDs incl. elite */,
           elite[], tags[] /* shadow, shadoweligible, mega, legendary, mythical, ultrabeast, regional, untradeable, … */,
           family?, released, dmax?, gmax? }
Move     { name, type, fast, pvp: { power, energy, turns? | buffs?, buffTarget?, chance? },
           pve: { power, dur /* s */, energy } | null /* null = PvP-only variant, e.g. *_PLUS */ }
RankEntry{ id, score, moves: [fast, charged1, charged2], rating?, scores? /* [lead, closer, switch, charger, attacker, consistency] */,
           wins?, losses? /* top-5 opponent ids */, product? }
LeekEvent{ eventID, name, eventType, heading, link, image, start, end /* no 'Z' = local wall-clock time */, extraData? }
LeekRaid { name /* "Shadow Alolan Sandslash", "Mega Malamar" */, tier /* "5-Star Raids" */, canBeShiny, types[], combatPower, boostedWeather[], image }
```

### ID conventions
- Species ids = PvPoke `speciesId`. Shadow = `<id>_shadow` (separate entry, same base stats; apply ×1.2 atk / ×5/6 def in maths). Mega = `<id>_mega`, `_mega_x`, `_mega_y`. Regional = `_alolan`, `_galarian`, `_hisuian`, `_paldean`.
- Move ids = PvPoke `moveId` (fast moves have **no** `_FAST` suffix; PokeMiners does, stripped in the pipeline). Hidden Power is split per type by PvPoke.
- LeekDuck/GBL display names are mapped by `resolveName()` / `matchLeague()`. Add cases there, not ad hoc in pages.

```ts

            dynamax?: 'dmax'|'gmax', bestBuddy?, ivs: [atk, def, sta], level, fast?, charged: string[],
```

- **Poke Genie re-import** (`mergePokeGenie`): replaces all `source==='pokegenie'` rows, keeps `manual` rows, and carries user flags (`raidReady, pvpReady, shiny, forTrade, dynamax, bestBuddy, notes, nickname`) + `uid` to the new row matching `speciesId|ivs|shadow-state`.
- Backups: Roster → "Export backup" (JSON `{app, version, exported, roster}`); Trade → "Share list" → Pokédex backup (JSON).
- Bump the key suffix (`-v2`) + write a migration if a schema change is not backward compatible.

## 6. Algorithms (where to tweak)

- **Raid counters** `calc.simulate()` — GamePress-style: DPS0 from fast/charged cycles, energy-from-damage correction `(CDPS−FDPS)/(CEPS+FEPS)·(0.5−x/HP)·y`, boss incoming DPS `y` from boss moveset with +2 s gaps, `TDO = DPS·HP/y`, score `ER = (DPS³·TDO)^¼`. Boss movesets exclude elite moves and Return/Frustration. Raid tier CPM/HP table in `raidTier()`.
- **Max Battles** `raid.maxAttackers/maxTanks` — heuristic (Atk × STAB × effectiveness of the fast-move type; bulk ÷ incoming multiplier). Not a simulation.
- **PvP IV rank** `calc.pvpIvRank()` — highest level ≤ cap (50, or 51 best buddy), stat product = atk·def·floor(hp), rank among 4096 spreads.
- **My team** `pvp.myCandidates/bestTeams` — value = PvPoke score × (SP% )³ × (ML: level/50) × 0.93 if fast move differs; mons above the cap level are excluded (can't power down); triples searched from top 18; penalty 6/shared weakness, 15/type nobody resists; no duplicate species.
- **Meta cores** `pvp.suggestTeams` — top leads × switches × closers with the same penalties; variety caps.
- **Trade spares** `dex.spares` — `forTrade` + duplicates (keep best IV copy); excludes shadow, lucky, mythical/untradeable, favorite, best buddy, raid/pvp-ready.

## 7. Data sourcing & evidence policy

Goal: official data first, community data only when it's *backed*. Speculation never reaches the site.

### Source tiers
| Tier | What | Examples | Use |
| --- | --- | --- | --- |
| **T0 Official** | Niantic/TPC announcements | `pokemongolive.com/feed` RSS & news posts, official in-game news | Facts about events/dates/bonuses. Always wins over lower tiers. |
| **T1 Datamined (structured)** | Game files | PokeMiners `game_masters/latest.json` (+ its git history for diffs), PokeMiners APK text | Stats, moves, forms, flags. Factual about *files*, but **unreleased ≠ confirmed** → mark `datamined`. |
| **T2 Curated aggregators** | Sites that cite T0/T1 | LeekDuck (via ScrapedDuck), PvPoke rankings | Structured feeds we already consume. |
| **T3 Community research** | Posts with method + data | r/TheSilphRoad posts flaired *Research*/*Datamine*/*Verified*, Silph-style studies, known datamining accounts | Only as **remarks**, only when they meet the evidence rules below. |
| **T4 Speculation** | Hopes, guesses, "leaks" without files, "I think…" | random Reddit/Twitter/YouTube comments, AI-generated sites | **Never ingested.** |

### Evidence rules for a remark to be published
1. Has a **source URL** and a **tier**.
2. Evidence type is one of: `official`, `game-file` (points at a file/field or GM diff), `study` (method + sample size stated, n ≥ 100 for rates), `repro` (≥ 2 independent reports with screenshots/video). Anything else → rejected.
3. T3 claims need **corroboration**: a second independent T3 source, or a matching T0/T1 fact (e.g. a claimed move rebalance must appear in the game-master diff). Game-master diff is the preferred auto-verifier.
4. Status is explicit: `confirmed` (T0, or T1 live in game), `datamined` (in files, not announced), `study` (measured), `disputed` (conflicting backed sources). Expired/overridden remarks get `expires`/`supersededBy`.
5. When a higher tier contradicts a remark, the higher tier wins and the remark is marked `disputed` or removed.

### Proposed implementation (not built yet)
- `data/remarks/*.yaml` (committed, human-reviewed) → pipeline validates the schema and emits `public/data/remarks.json`:
  ```yaml
  - id: 2026-10-xerneas-geomancy
    subject: { species: xerneas }          # or move / event / feature
    claim: "Geomancy available via Elite TM from Oct 2026"
    status: datamined                      # confirmed | datamined | study | disputed
    tier: T1
    evidence: game-file
    sources: [https://github.com/PokeMiners/game_masters/commit/<sha>]
    added: 2026-09-29
    expires: 2026-12-01
  ```
- `scripts/gm-diff.mjs`: diff yesterday's vs today's game master → auto-generate `datamined` remarks (new moves, stat/move changes, new Dynamax/Gigantamax forms, new shinies) — these are backed by definition.
- `scripts/collect-candidates.mjs`: pulls T0 RSS + (optional) Reddit posts from r/TheSilphRoad with *Research/Datamine* flair (Reddit blocks anonymous JSON; needs a free personal "script" OAuth app, credentials in GitHub Secrets) into a **review queue** (`data/remarks/_queue.json`) — never straight to the site. A human (or Claude, applying the rules above) promotes items into `data/remarks/`.
- UI: a small "Notes" panel on species/raid/event views showing remarks with a status badge and source link.

## 8. Conventions
- Game-data lookups go through `useGameData()`; never fetch `public/data` directly from pages.
- Name/league matching lives in `lib/names.ts`; maths in `lib/calc.ts` (pure functions, no React).
- Heavy lists: page at 100–200 rows (`limit` state) — the roster can be 3,000+ mons.
- Every page must work with an empty roster (show `<Empty>` guidance).
- Keep attribution in the footer; this is a personal, non-commercial site.
